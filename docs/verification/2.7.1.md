# 2.7.1 local verification — 2 November 2026

This build was tested on the connected Xiaomi 23053RN02A running Android 15, then installed over the existing app. The release assets use the APK verified below.

## Automated checks

- Python: 117 tests passed. One existing Starlette/httpx deprecation warning remains.
- JavaScript: 25 tests passed.
- Android: 59 unit tests passed; debug lint passed with zero errors and two warnings; release assembly passed.
- Regression tests reproduce missing artwork fallbacks, WebM/MP4 container handling, metadata preservation, label-channel credits, Spotify pagination, repeated recordings, official matching, YouTube album grouping, and folder deletions.

## Connected-phone checks

- Backed up all 88 original audio files before repair (402,405,231 bytes). The backup and device diagnostics remain in the git-ignored `.device-test-inspect` directory.
- Repaired all 88 existing files without downloading their audio again. Android's `MediaMetadataRetriever` read embedded covers and album tags from all 88. Automatic matching identified 87 albums; the remaining edited upload was tagged from [Saregama's original release credits](https://www.youtube.com/watch?v=UnX5imZNBzU), which identify *Sangam* (1996). The final native audit found no missing covers or album tags.
- Android's music index reports repaired album and album-artist tags. Repaired audio prepared and played through the native Android player.
- After unlocking the phone, a screen check exposed Library thumbnails still depending on remote hosts. Saved rows now read embedded pictures from their local audio files, with the file timestamp in the image cache key. Regression tests cover missing remote URLs, catalog image hosts, and path traversal. The installed release visibly displayed covers for FLEXIONI, Sad People, No Reply, Past Life, and subsequent rows. Sad People played and its on-screen position advanced; playback was paused after testing.
- A temporary fixture deleted through the selected Music folder disappeared from Saved. A second fixture deleted through Saved disappeared from its linked folder. Both tests passed against Android's actual document provider; no fixture rows remain.
- The complete 250-track Spotify playlist preview produced 244 unique official matches, four repeated recordings, and two unmatched tracks. The preview retained album, EP, single, and compilation release types. It did not stop at the embed's 100-track limit.
- Downloaded two new Spotify-matched tracks through the real on-device token provider and downloader: M4A/AAC and Original/Opus. Android read their embedded covers; both carried the correct album, album artist, track number, and release date. Test downloads and their folder copies were removed afterwards, leaving the original 88 library rows.
- The entire 250-track audio batch was not queued; full metadata enumeration/matching and representative downloads were verified separately.

Device instrumentation and its audio fixture live only in the debug source set. The installed release APK excludes both, has debugging disabled, and preserves the existing signing identity and app data. The phone's original USB stay-awake setting was restored.
